### 起因

- 目前Javascript端`TSPL`指令的封装基本都是和佳博提供的sdk差不多，但也有点旧了，而`CPCL`指令相关的封装很少，所以参考着一并封装了下。

### 变动

- 编码直接用[iconv-lite](https://github.com/ashtuchkin/iconv-lite)，其本身只支持`nodejs`
  ，所以还需要用[vite-plugin-node-polyfills](https://www.npmjs.com/package/vite-plugin-node-polyfills)插件来适配。
- `TSPL`在原有基础上用`模板字符串`来重新封装了下，改为链式调用。
- `CPCL`则是参考`TSPL`来自己封装了下。

### 示例

- `uniapp vue3 非ts`版本，蓝牙链接打印，目前有实机测试安卓和小程序，IOS没有测试，而且也仅仅是文本、条码、二维码、位图这些基本测试。
- 目前自己遇到了两种场景：
    - 项目各个地方都有可能引用组件弹窗中使用蓝牙来打印物料，示例对应着`componentes/popup`
    - 特定页面来使用蓝牙，用完就关闭，示例对应着`pages/single`
- 上述页面都是一键链接蓝牙，不需要自己再选择哪个蓝牙，所以需要先测试好蓝牙的设备名称、广播ID、服务ID、特征值ID，放到
  `commonConst`中，可以去`pages/manual`页面中调试选择自己的蓝牙并打印蓝牙的信息，蓝牙一般是有多个服务，然后每个服务又对应多个特征值，一般可以先尝试第一个，找到其特征值是
  `write:true`可写的，不好找的话可以直接联系打印机官方技术询问。
- 位图这个占用了很长时间来测试，网上很多文章是说一行一个命令来写入，实际测试并不需要，步骤是：
    - 通过`uni.getImageInfo`来获取要打印的图片信息
    - 通过`uni.createCanvasContext`来将图片画到画布上
    - 通过`uni.canvasGetImageData`来获取图片的二进制信息
    - 然后就进入图片处理了（个人只是勉强理解）
        - 宽度处理，每行字节数 = `ceil(宽度/8)`。宽度不是8的倍数也没关系，但**每行必须独立按字节对齐**，行尾多出的位按“不打印”(1)补足。早期版本是把整张图摊平成一个比特流再每8位切一刀，宽度不是8的倍数时行与行之间会累积错位（图像斜切），而且总字节数少于头部声明的 `宽度(字节)*高度`，打印机就会把后面的命令当成图像数据吃掉
        - 透明处理，先按白纸做alpha合成 `c = c*a + 255*(1-a)`。PNG的透明像素RGB是`(0,0,0)`，不看alpha会被整块印黑
        - 计算灰度，灰度>128视为白色（不打印，存1），否则为黑色（打印，存0）
        - 按行将上方的二进制数组合并成字节
        - 最后写入指令
- 蓝牙有长度限制，所以需要分批来写入，而且每次写入增加了一个延迟100ms。
- `uniapp`蓝牙部分`off取消监听`的多个方法只支持微信小程序，app端不支持，可能导致重复监听。

### 注意事项

- 内容里的特殊字符，`TSPL`和`CPCL`的规则不同：
  - `TSPL`的文本/条码/二维码内容是用双引号包起来的，所以内容里的双引号必须由**调用方**写成`\["]`。可以直接调用静态方法`TSPL.escape(data)`，它把双引号、CR、LF分别转成`\["]`、`\[R]`、`\[L]`（`\[L]`是“V5.10EZ”后的写法，如果机器固件较旧、换行打不出来时改成`\[A]`试下）。
  - `CPCL`的内容不加引号（`T ...` / `B ...` / `B QR ...`后面直接跟内容），所以双引号本身无害，也没有这套转义。
  - 两边共同的一条：内容里最好不要出现裸的CR/LF，它会被当成命令结束符把一条命令切成两条，多行文字请用多条`text`指令分别指定`y`坐标。
- 内容编码要跟**字库**匹配：内置中文点阵字体本身就是内码字库（`TSS*.BF2`简体=GB码、`TST24.BF2`繁体=大五码），所以现在内容统一用`gb18030`对应简体字体，换繁体/韩日字库就得换编码。TSPL2虽然支持`CODEPAGE UTF-8`，但**省不掉转码**（只对Unicode的TTF字体有意义）；CPCL对应的开关是`COUNTRY CHINA`/`BIG5`。
- `CPCL`的位图数据要做反转处理。`TSPL`的`BITMAP`和`CPCL`的`CG`对“一个位代表什么”的约定是**相反**的：
  - `TSPL`是 0=打印/1=不打印
  - `CPCL`是 1=打印/0=不打印
- 示例`logo.png`打印正常；`marker.png`打印不正常有两层原因：
  - 它的透明背景有1810个像素（占44%）`alpha=0`而RGB为`(0,0,0)`，以前不看alpha就被当成黑色整块打印出来，目前已改为按白纸做alpha合成
  - 但`marker.png`这张图本身偏浅（浅绿色，最暗的像素灰度也有137.7，高于128阈值），阈值化后没有一个点需要打印，所以现在会印成**空白**。
  - 浅色图要在只支持黑白的打印机上出效果，需要加深原图或者引入抖动(dithering)处理。
- 位图数据直接`push`即可，不必经过`intToByte()`：它只有在把命令数组交给**原生安卓插件**时才需要（那种接口要传`byte[]`，取值必须是-128~127）；普通蓝牙写入走`batchWrite`→`ArrayBuffer`，与平台无关。

### 修改待实机验证

目前部分功能有改动，但是当前手上又没有打印机，下面这些改动只做到**命令串层面**的验证，**没有上过实机**，建议测试后使用：

- `BLOCK`（段落自动换行/对齐）—— 新增，**要求机器支持2012/11之后的TSPL2**，可以先打一张自检页（`SELFTEST`）看固件版本；它的`alignment`参数和`text`的一样，也是**V6.73EZ之后**才支持（不传就不受影响）；另外只给`alignment`不传`space`时库会自动补`space=0`（0=不调行距），这个"显式传0"和"完全不传"在固件里是否等价，也顺便验一下
- `text`/`textRotation` 的 `alignment` —— 新增的是这个**可选参数**，它要求 **V6.73EZ 之后**才能向这个参数传值，小于这个版本的此参数不要传递即可
- `TSPL.escape(data)` 转义 —— 新增。重点验内容里带**双引号**时能正常打印（`\["]`）；CR/LF的转义（`\[L]`/`\[A]`）和固件版本有关，两份手册写法不一致，见方法注释
- `limitFeed` 一族 —— 新增 `limitFeedMm`/`limitFeedDot` 两个方法，对应 `LIMITFEED n mm` 和 `LIMITFEED n dot`（后者要求 **V6.34 及以后**）；公制/英寸的用法和以前一样。新增的后两个参数 `minpaper`/`maxgap` 要成对传（只给一个会抛错），对应 **V6.98.7 EZ 之后**的固件，两个都不传时发出的命令和以前完全一样
- `direction` 的 `m` 改为可选 —— 修改：`DIRECTION n[,m]` 里的镜像参数，以前不传 `m` 会发出 `DIRECTION 0,undefined`，现在不传就不拼进命令（TSPL2手册的范例就是 `DIRECTION 0`）
- `print` 的 `m`/`n` —— 修改：`print()` 现在发 `PRINT 1`（原来是 `PRINT 1,1`，等价于把 `n` 省掉），`print(m,n)` 里 `n` 是"每个序号重复打印几张"。**`n` 省略时打印机实际打几张，三本手册都没写明**，这条只能上实机看
- `BARCODE` 的 `alignment`、`QRCODE` 的 `model,mask`、`BOX` 的 `radius` —— 新增的三个可选参数，都是不传就不拼进命令。`QRCODE` 的 `mask` 不能单独传（命令里 `model` 那一位没法空着），只给 `mask` 会抛错。版本上：`BOX` 的 `radius` 手册标了**要求 V5.28EZ 以后**；`BARCODE` 的 `alignment`（还有 `readable` 的 2居中/3右对齐这两个值）是**较新固件才有**的，2009版TSPL2手册里连语法都还没有这两个值，2014版才有；`QRCODE` 的 `model,mask` 手册没标
- 位图的**行补齐**与**透明合成** —— 修的是已有功能：宽度不是8的倍数的图（原先会斜切并把后续命令吃掉）、带透明背景的图（原先透明区整块印黑）。示例的 `logo.png` 是72×72（8的倍数、只有4个透明像素），**看不出差别**，建议用宽度不是8
  的倍数的图、以及带透明背景的图各打一张对比
- `intToByte` 去掉平台分支 —— 修改：只有原生安卓插件才需要，目前项目示例app端也是套壳，所以不需要调用此方法

### 参考

- 佳博技术提供的`uniapp`示例，汉印技术提供的`uniapp`版本只有`安卓原生插件`，而其纯js版本则代码比较老，可以直接联系两家的客服技术询要。
- [cpcl-bluetooth-print](https://github.com/codersmoixan/cpcl-bluetooth-print)中的部分`CPCL`封装。
- [BluetoothPrinter](https://gitee.com/booltrue/bluetooth-printer/tree/master)，这个除了低功耗蓝牙，还有原生安卓蓝牙操作。
- 编程手册放到`doc`目录下了，其中TSPL存在两代指令集：
  - `TSPL2指令集(中文版)`（TSC官方，263页）—— **TSPL2**，一手资料。要查"某条指令是不是TSPL2才有的"，看它**最后两页的`Update History`**（PDF第260~261页），那里按日期列出了每条指令是什么时候加进TSPL2的
  - `佳博标签打印机编程手册TSPL v1.0.8` —— **TSPL1**：典型的TSPL手册，只有系统设定、标签格式、状态询问（RS-232）三类章节，并且明确区分“for TSPL2 printers”与“for TSPL printers”（条码类型表，第20页）
  - `TSPL 编程手册_REV.1.0`（汉印）—— 实际是 **TSPL2谱系的文档**：章节结构同TSPL2，含BASIC指令及函数、文件管理、打印机全局变量等；`BLOCK`那一段还是英文原文（该手册其余部分是中文），虽然名字里没有“2”
- 手册之间要对照着看：例如`DIRECTION`，佳博TSPL手册只写了`DIRECTION n`（并把n说成“出纸和打印字体的方向”），汉印手册和TSPL2手册都写`DIRECTION n[,m]`（n=打印方向，m=镜像0正常/1镜像）。三本的示意图其实一致，按TSPL2看是汉印的参数说明对，佳博那份漏了可选的`m`。
- 同一本手册的**不同年份版本之间也会变**，不能只拿一本下结论：`TSPL/TSPL2 Programming` 的2009版和2014版里，`BARCODE` 的 `human readable` 就从 `0/1` 变成了 `0不显示/1左/2居中/3右`，而且2014版才多出可选的 `alignment` 参数——但2014版手册的 `Update History` 里**并没有**记这次改动（那条 `Revise BARCODE command` 讲的是新增TELEPEN等条码类型），所以查不到对应的固件版本号，只能按手册年份说。
